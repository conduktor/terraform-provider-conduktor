# conduktor_gateway_alias_topic_v2

Resource for managing Conduktor Gateway Alias Topics.
This resource allows you to create, read, update and delete alias topics in Conduktor Gateway.

## Example Usage

### Simple alias topic on the passthrough virtual cluster
```terraform
resource "conduktor_gateway_alias_topic_v2" "simple_alias" {
  name     = "simple-alias"
  vcluster = "passthrough"
  spec = {
    physical_name = "my-topic"
  }
}
```

### Complex alias topic on a virtual cluster with an explicit physical cluster
```terraform
resource "conduktor_gateway_alias_topic_v2" "complex_alias" {
  name     = "complex-alias"
  vcluster = "vcluster_sa"
  spec = {
    physical_name    = "my-topic"
    physical_cluster = "main"
  }
}
```

## Schema

### Required

- `name` (String) The name of the alias topic, must be unique within the virtual cluster, acts as an ID for import
- `spec` (Attributes) Alias topic specification (see [below for nested schema](#nestedatt--spec))
- `vcluster` (String) The name of the virtual cluster the alias topic belongs to

<a id="nestedatt--spec"></a>
### Nested Schema for `spec`

Required:

- `physical_name` (String) The physical topic name on the Kafka cluster that this alias topic maps to

Optional:

- `physical_cluster` (String) The physical Kafka cluster hosting the physical topic; only needed for Partner virtual clusters, omit for Standard virtual clusters

## Import

In order to import an existing Conduktor Gateway Alias Topic, you need to know the alias topic name and virtual cluster name pair.

The import ID is constructed as follows: `<alias_topic_name>/<vcluster>`.

For example, using an [`import` block](https://developer.hashicorp.com/terraform/language/import) :
```terraform
import {
  to = conduktor_gateway_alias_topic_v2.example
  id = "my-alias/my-vcluster" # Import <alias_topic_name>/<vcluster> Alias Topic
}
```

Using the `terraform import` command:
```shell
terraform import conduktor_gateway_alias_topic_v2.example alias_topic_name/vcluster_name
```
